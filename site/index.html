C# examples

Connect. Transfer.
Serve.

Install the package in a .NET 10 project. These examples use the Tedd.SMB3 namespace and read the password from TEDD_SMB_PASSWORD.

dotnet add package Tedd.SMB3
Read and write a share
using Tedd.SMB3;

string password = Environment.GetEnvironmentVariable(
    "TEDD_SMB_PASSWORD") ?? throw new InvalidOperationException(
    "Set TEDD_SMB_PASSWORD.");

await using var client = await SmbClient.ConnectAsync(
    "server", "files", new()
    {
        UserName = "smbuser",
        Password = password,
        Port = 1445,
        Encrypt = true
    });

await client.WriteAllBytesAsync("hello.txt",
    System.Text.Encoding.UTF8.GetBytes("Hello from C#"));
byte[] data = await client.ReadAllBytesAsync("hello.txt");
foreach (var entry in await client.ListDirectoryAsync())
    Console.WriteLine($"{entry.Name}: {entry.Length} bytes");
await client.MoveAsync("hello.txt", "renamed.txt");
await client.DeleteAsync("renamed.txt");
Export an existing directory
using System.Net;
using Tedd.SMB3;

string password = Environment.GetEnvironmentVariable(
    "TEDD_SMB_PASSWORD") ?? throw new InvalidOperationException(
    "Set TEDD_SMB_PASSWORD.");

await using var server = new SmbServer(new()
{
    Shares = [new("files", SmbDirectoryProvider.Create(args[0])) { Writable = true }],
    UserName = "smbuser",
    Password = password,
    ListenAddress = IPAddress.Any,
    Port = 1445,
    RequireEncryption = true
});

using var stop = new CancellationTokenSource();
Console.CancelKeyPress += (_, e) =>
{
    e.Cancel = true;
    stop.Cancel();
};
await server.RunAsync(stop.Token);
Read a large file with bounded memory
// Use a connected SmbClient from the first example.
await using var remote = await client.OpenAsync("large.bin");
await using var local = File.Create("download.bin");
byte[] buffer = new byte[64 * 1024];
long offset = 0;
int count;
while ((count = await remote.ReadAsync(buffer, offset)) > 0)
{
    await local.WriteAsync(buffer.AsMemory(0, count));
    offset += count;
}

The server example exposes a writable share on all IPv4 interfaces. Choose a specific listen address and restrict filesystem and network access to the intended clients. The defaults are loopback, port 445, read-only, and encryption required.

Application-defined storage

One server.
Multiple providers.

Register up to 256 named shares, each backed by an ISmbShareProvider. Supply your own implementation for SQL-backed documents, object storage, memory, or a remote API. A physical directory is optional.

Pass application providers into your server factory. Here, documents is writable; reports and the directory share are read-only.

Register multiple shares
using System.Net;
using Tedd.SMB3;

public static class ShareHosting
{
    public static SmbServer Create(
        ISmbShareProvider documents,
        ISmbShareProvider reports,
        string exportPath,
        string userName,
        string password) => new(new SmbServerOptions
    {
        Shares =
        [
            new("documents", documents) { Writable = true },
            new("reports", reports),
            new("files", SmbDirectoryProvider.Create(exportPath))
        ],
        UserName = userName,
        Password = password,
        ListenAddress = IPAddress.Loopback,
        Port = 1445,
        RequireEncryption = true
    });
}

Your provider's OpenFile can return this read-only handle for a BLOB loaded from SQL or an API. This example keeps the complete BLOB in memory.

An application-backed file handle
using Tedd.SMB3;

public sealed class BlobFile(ReadOnlyMemory<byte> data) : ISmbFile
{
    public long Length => data.Length;

    public ValueTask<int> ReadAsync(
        Memory<byte> buffer, long offset,
        CancellationToken cancellationToken)
    {
        cancellationToken.ThrowIfCancellationRequested();
        ArgumentOutOfRangeException.ThrowIfNegative(offset);
        if (offset >= Length) return ValueTask.FromResult(0);

        int count = (int)Math.Min(buffer.Length, Length - offset);
        data.Slice((int)offset, count).CopyTo(buffer);
        return ValueTask.FromResult(count);
    }

    public ValueTask WriteAsync(
        ReadOnlyMemory<byte> buffer, long offset,
        CancellationToken cancellationToken) =>
        throw new NotSupportedException("Read-only file.");

    public void SetLength(long length) =>
        throw new NotSupportedException("Read-only file.");

    public void Flush() { }
    public void Dispose() { }
}

ISmbShareProvider supplies logical paths, directory enumeration, metadata, stable file identities, capacity, and namespace operations. ISmbFile supplies positional I/O and handle lifetime. SQL queries, transactions, and storage connections belong to your provider; a SQL provider is not bundled.

SmbDirectoryProvider.Create(path) selects WindowsDirectoryProvider or LinuxDirectoryProvider. Custom providers require neither a local path nor a native file handle. The application owns provider resources and keeps them alive until server shutdown.

Share registration belongs to this server instance and does not create or modify Windows shares. Use an available address and port; the system SMB service may already occupy port 445. Providers are selected at construction; live provider replacement is not supported. See the provider interfaces and hosting reference.

Console host

A directory becomes
a network share.

Clone the source and build the host with the .NET 10 SDK. Create the export directory first, set a password in the process environment, then start the foreground server.

Windows · PowerShell
# From the cloned repository.
dotnet build Tedd.SMB3.slnx -c Release
New-Item -ItemType Directory -Force D:\Exports\files
$credential = Get-Credential -UserName smbuser
$env:TEDD_SMB_PASSWORD = $credential.GetNetworkCredential().Password
dotnet src/Tedd.SMB3.Host/bin/Release/net10.0/Tedd.SMB3.Host.dll serve `
  --root D:\Exports\files --share files --user smbuser `
  --bind 0.0.0.0 --port 1445 --writable
Linux · Bash
# From the cloned repository.
dotnet build Tedd.SMB3.slnx -c Release
mkdir -p "$HOME/smb-export"
read -rsp 'SMB password: ' TEDD_SMB_PASSWORD; echo
export TEDD_SMB_PASSWORD
dotnet src/Tedd.SMB3.Host/bin/Release/net10.0/Tedd.SMB3.Host.dll serve \
  --root "$HOME/smb-export" --share files --user smbuser \
  --bind 0.0.0.0 --port 1445 --writable

Omit --writable for a read-only export. Ctrl-C stops the host. Port 1445 avoids the system SMB listener; port 445 supports conventional UNC access and may require elevated binding privileges on Linux.

Native filesystem access

Mount once.
Use ordinary files.

Start the server above, replace server with its hostname or IP address, and use the same smbuser password. Both examples request encryption.

Windows

Alternate TCP ports require Windows 11 24H2 / Windows Server 2025 or later with New-SmbMapping -TcpPort. Use port 445 on clients without that parameter.

PowerShell · map S:
$credential = Get-Credential -UserName smbuser
New-SmbMapping -LocalPath 'S:' `
  -RemotePath '\\server\files' -TcpPort 1445 `
  -UserName $credential.UserName `
  -Password $credential.GetNetworkCredential().Password `
  -RequireIntegrity $true -RequirePrivacy $true `
  -Persistent $false

Get-ChildItem S:\
Get-SmbConnection | Where-Object ShareName -eq 'files'

# Disconnect when finished.
Remove-SmbMapping -LocalPath 'S:' -Force

For a server listening on 445, omit -TcpPort 1445. File Explorer can then use \\server\files. Windows policies must permit NTLMv2 authentication.

Linux

Install your distribution’s cifs-utils package. Mounting requires root or the appropriate mount permissions and kernel SMB 3.1.1 support.

Shell · mount CIFS
sudo mkdir -p /mnt/tedd-smb
# Prompts for the SMB password; it is not in shell history.
sudo mount -t cifs //server/files /mnt/tedd-smb \
  -o "username=smbuser,vers=3.1.1,sec=ntlmssp,seal,port=1445,uid=$(id -u),gid=$(id -g)"

ls -la /mnt/tedd-smb
findmnt /mnt/tedd-smb

# Unmount when finished.
sudo umount /mnt/tedd-smb

seal requests SMB encryption. For port 445, omit port=1445. Match local mount permissions to the users who need access.

References: Microsoft New-SmbMapping · mount.cifs manual.

Capabilities & operating limits

Focused on
file transfer.

Per-share storage providers, NTLMv2 or native Kerberos authentication, and IPC$/srvsvc share enumeration. Use it for managed file sharing where these protocol capabilities fit your workload.

01 / Files

Read, write, manage

Create and list directories. Read, write, flush, truncate, rename, and delete files. Use explicit 64-bit offsets and query or update timestamps and attributes.

02 / Sessions

Bounded connections

64 KiB transfers, 32 credits, 32 compound commands, 64 trees and 1,024 handles per connection; 32 connections by default. Requests on each connection execute in order.

03 / Storage

Provider-owned access

Shares have separate write and authorization policies. Directory providers reject traversal and symbolic links; protect exports from untrusted local directory replacement. Application providers enforce their backing store's access and concurrency rules.

Deployment considerations

Shares register application storage providers or the included Windows and Linux directory providers. Authentication supports NTLMv2 or native Kerberos; external authentication requires an explicit share authorizer. Unchained LZNT1 compression is negotiated per connection. Guest access, leases/oplocks, byte-range locks, durable handles, multichannel, change notifications, alternate streams, and Windows ACL management are outside this implementation. Sessions and handles cannot be recovered after reconnect.

The Linux directory provider’s logical creation/change timestamps and hidden/archive attributes use user.tedd.smb3.* extended attributes. The backing filesystem and backups must preserve them. Independent server instances need separate exports.
